# 输出模板

只有在相关设计分支已经解决，或用户明确要求综合时，才使用这些模板。

## 简洁的模块决策

```markdown
### <模块>
- 职责：
- 拥有：
- 不拥有：
- 核心不变量：
- 公共 API：
- 主要权衡：
- 延期风险：
```

## 架构综合

```markdown
## 模块图
<语义模块和适配器>

## 所有权 / 权威关系
<每项关键状态的事实来源>

## 主要数据路径
<一到两条代表性路径>

## 关键不变量
<简短列表>

## 成本 / 热点路径
<已知架构成本，以及有测量依据的瓶颈>

## 决策
<已同意的边界 / API>

## 延期风险
<明确延期的问题>
```

## ADR 风格决策

```markdown
# 决策：<标题>

## 背景
<问题和约束>

## 决策
<选定的边界 / API / 模型>

## 原因
<知识、不变量和成本方面的推理>

## 考虑过的替代方案
<有实质差异的方案>

## 影响
<哪些事情变得更容易或更困难>

## 未解决风险
<有意保留的问题>
```
